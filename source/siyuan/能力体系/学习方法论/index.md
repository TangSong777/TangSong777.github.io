> 这套方法用于以后学习 NumPy、OpenCV、PyTorch、C++、Linux、信号处理等新能力。核心不是“看完一份资料”，而是完成一个可验证、可归档、能产生能力证据的学习闭环。

## 1. 明确目标：先定义能力，不先堆知识

学习文档开头必须说明项目价值、当前等级、目标等级、最终独立任务，以及暂不学习的内容。

## 2. 拆成学习阶梯：先零件，再系统

固定顺序：环境与最小示例 → 基础概念与核心 API → 单点练习 → 组合练习 → 项目场景 → 独立新任务。每一步包含目标、示例、运行观察、自己修改和易错点，不能一开始直接丢完整项目代码。

## 3. 学习过程必须留下证据

- **运行证据**：输出结果、图像、日志或报错
- **修改证据**：修改参数、结构或输入后的结果变化
- **解释证据**：用自己的话回答“是什么、为什么、什么时候用”
- **问题证据**：记录卡住的位置和修正过程

AI 可以提供示例和提示，但不能替代运行、修改和解释。

## 4. 按五层掌握推进

|层次|要完成什么|证据|
| ------| ----------------------| ----------------------|
|输入|看懂概念和示例|能复述基本概念|
|复现|自己重新运行/敲写|有真实运行输出|
|修改|改参数、输入或结构|能说明结果变化原因|
|解释|讲清原理和边界|能回答“为什么”|
|创造|独立设计新任务或方案|有独立成果和实验记录|

## 5. 学完先验证，再评估等级

检查完成项 → 收集运行输出 → 检查参数/结构修改 → 提出 2-3 个解释问题 → 判断等级 → 给出下一等级的独立任务。完成学习文档不等于掌握。

## 6. 归档不是复制，而是提炼

- **学习文档**：保留完整过程、输出和问题，重命名为“已归档”
- **知识笔记**：提炼稳定的概念、函数、场景和易错点
- **能力地图**：记录等级、证据、日期、项目应用和下一目标

## 7. 每次归档必须校验

检查学习文档链接、知识笔记分类、能力地图证据、日记原文是否未被修改，以及是否存在空块、重复内容或断链。

## 8. Agent 固定工作流

```text
判断长期价值与项目连接
    ↓
盘点当前等级和知识缺口
    ↓
生成循序渐进学习文档
    ↓
学习并留下证据
    ↓
按三类证据验证
    ↓
评估等级与下一阶段任务
    ↓
归档学习文档、提炼知识笔记、更新能力地图
```

目标不是让知识库越来越大，而是让每次学习都转化为**可复用知识 + 可验证证据 + 更强的独立能力**。

## 9. 案例：NumPy 流程复盘

第一版直接进入 PPG 实战，难度过高；根据反馈改为 14 步循序渐进练习；每步增加运行笔记和参数实验；将稳定内容提炼进本专项文档；依据证据将 NumPy 从 L0 更新为 L2；保留完整练习文档作为学习档案。以后默认采用循序渐进流程，不再直接把复杂项目当作入门练习。

## 10. 笔记整理：从学习文档到规范笔记

> 学习文档归档后，需要将知识点提炼进专项知识笔记。这份方法论来自数据结构专项的整理实践。

### 10.1 核心原则：知识链条优先

笔记必须有清晰的**逻辑主线**，知识点按依赖关系排列：

- **基础概念放最前**：如"可变与不可变"是理解 list/tuple/set/dict 所有行为的前提，必须放在第一章
- **独立概念按模块拆分**：每种容器各自成章，有自己的完整知识体系
- **每章结构固定**：定义 → 创建 → 操作 → 场景 → 易错

### 10.2 内容分层

|层次|内容|归属位置|
| ----------| ------------------------------| ------------------------|
|核心知识|概念、语法、API、对比表|正文（## 一/二/三...）|
|个人心得|类比、体会、项目连接|附录（A.1/A.2...）|
|学习证据|运行输出、修改记录、口头解释|附录末尾（归档证据）|

**关键**：个人笔记是"附属与体会"，不应打断正文的知识链条。

### 10.3 正文规范

每章以一句话定义开头（blockquote），每小节有独立编号：

```markdown
## 二、列表 list（可变序列）

> 列表是 Python 中最常用的容器：有序、可变、可容纳任意类型。

### 2.1 创建与基本操作
### 2.2 增删改查
### 2.3 切片
...
```

- 表格用于：类型对比、方法速查、选型决策
- 代码示例标注注释，说明"为什么"而非只写"是什么"

### 10.4 个人心得融入正文

标题为 `附录：学习笔记与心得`，引言说明来源文档并附链接：

```markdown
## 附录：学习笔记与心得

> 以下为 ((xxx "Python容器学习（已归档）")) 中的个人理解。

### A.1 变量本质：标签而非盒子
...
### A.6 归档证据摘要
**运行输出：** ...
**主动修改：** ...
**口头解释：** ...
```

1. **读取源文档**：获取归档前原文档的完整内容

1. **读取源文档**：获取归档前原文档的完整内容
2. **提取知识点**：区分核心知识 vs 个人心得 vs 证据
3. **重建知识链条**：按依赖关系重新组织章节
4. **重写正文**：用规范格式重写，去除 Step 式练习痕迹
5. **整理附录**：将个人理解精炼为独立条目，附于末尾
6. **清理原文档**：归档文档保留原文，不修改内容

### 10.7 跨文档引用规范

> ⚠️ **必须使用思源笔记的双括号链接语法**，不要使用 Markdown 链接格式。

**正确**（产生双向链接）：

```

```
