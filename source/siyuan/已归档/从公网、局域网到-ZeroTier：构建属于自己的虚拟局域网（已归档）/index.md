# <span id="20260818174157-4yhmln4" class="siyuan-block-anchor" aria-hidden="true"></span>1. 为什么我需要一个自己的网络

我经常带着笔记本在宿舍、实验室、咖啡厅之间移动，但 NAS、电脑和服务器留在宿舍 LAN 中。目标不是“让笔记本永远使用宿舍 Wi-Fi”，而是：

> 无论笔记本当前接入哪一个互联网，都能安全、稳定地访问宿舍内的指定设备。

宿舍网络可以抽象为：

```text
宿舍 LAN：192.168.6.0/24（示例）
        │
        └── AX6/OpenWrt：192.168.6.1（示例）
              ├── NAS：192.168.6.100（示例）
              ├── PC：192.168.6.101（示例）
              └── Server：192.168.6.102（示例）
```

笔记本在实验室时可能拥有实验室的私网地址；它不能直接把 `192.168.6.100` 当作本地设备访问。需要先解决两个问题：

1. **路径问题**：实验室笔记本的数据如何到达宿舍 AX6？
2. **回程问题**：NAS 的回复如何回到实验室笔记本？

ZeroTier 的作用，是在现有 Internet 之上构建一个逻辑 Overlay，并通过 AX6 把这个 Overlay 网络路由到宿舍 LAN。但它不会替代物理网络、不会消除防火墙，也不会自动修复所有回程路由。

# <span id="20260818174157-qia9j84" class="siyuan-block-anchor" aria-hidden="true"></span>2. 什么是计算机网络

> 计算机网络是多个节点通过链路连接，并按照共同协议交换数据的系统。

- **节点**：能发送、接收或转发数据的实体，如笔记本、NAS、交换机、路由器、服务器。
- **链路**：两个节点之间传输比特的路径，如网线、Wi-Fi、光纤、运营商链路。
- **数据包**：网络把较大的通信内容拆成、封装成、再传输的一段段数据。
- **协议**：通信双方共同遵守的格式和规则，如 Ethernet、ARP、IP、TCP、UDP、DNS、HTTP。

一次通信不是“电脑直接连接电脑”，而是多层协议协作：

```text
应用数据：SSH 请求
   ↓
TCP：源端口、目标端口、可靠传输
   ↓
IP：源IP、目标IP、跨网络寻址
   ↓
Ethernet/Wi-Fi：本链路上的源MAC、目标MAC
   ↓
网卡与物理介质：发送比特
```

# <span id="20260818174157-u29lwsm" class="siyuan-block-anchor" aria-hidden="true"></span>3. IP、MAC、端口和数据包

## 3.1 三种地址分别解决什么问题

|概念|解决的问题|作用范围|示例|
| ----------| -------------------------| --------------| --------------|
|MAC 地址|本地链路上交给哪块网卡|当前二层链路|`aa:bb:cc:dd:ee:ff`（示例）|
|IP 地址|跨网络要到哪台主机/接口|三层网络|`192.168.6.100`（示例）|
|端口号|这台主机上的哪个服务|传输层|`22`​、`443`|

可以类比为：IP 是楼栋地址，MAC 是当前小区内的具体收件设备，端口是设备上的房间/服务。类比不能完全替代协议细节，但有助于建立层次感。

## 3.2 完整例子：访问宿舍服务器 SSH

假设宿舍笔记本为 `192.168.6.10`​，服务器为 `192.168.6.100`​，SSH 服务监听 TCP `22`：

```text
应用：笔记本发起 SSH 连接到 192.168.6.100:22
TCP：源端口临时选择 52341，目标端口 22
IP：源 192.168.6.10，目标 192.168.6.100
二层：源MAC=笔记本网卡MAC，目标MAC=服务器网卡MAC
```

如果目标不在本地网段，IP 目标仍然是远端服务器 IP，但二层目标 MAC 会改成默认网关接口的 MAC。**IP 决定逻辑目的地；MAC 决定当前一跳交给谁；端口决定目的主机上的服务。**

### 3.3 多层网络拓扑示例

假设笔记本访问宿舍服务器：

```text
笔记本：192.168.6.10
  │ Wi-Fi / 交换网络
AX6 LAN：192.168.6.1
AX6 WAN：100.64.12.3（示例）
  │ 宿舍上级网络
运营商 CGNAT：203.0.113.20（示例）
  │ Internet
目标服务器：198.51.100.50:22（示例）
```

数据包从笔记本发出时，IP 目标是 `198.51.100.50`​，因为它不在 `192.168.6.0/24`​，所以第一跳交给默认网关 `192.168.6.1`。在宿舍 LAN 这一跳，帧的目标 MAC 是 AX6 LAN 接口的 MAC；到达 AX6 后，AX6 再根据自己的 WAN 路由把数据交给上级网络。

若发生 NAT，AX6 可能把源地址从 `192.168.6.10`​ 改为 `100.64.12.3`​，运营商 CGNAT 再改为 `203.0.113.20`​。因此：**IP 地址负责标识当前逻辑通信的端点，MAC 地址只负责当前链路的一跳，端口负责区分目标主机上的服务；经过 NAT 后，源 IP/端口还可能被映射。**

# <span id="20260818174157-vszpzpy" class="siyuan-block-anchor" aria-hidden="true"></span>4. 什么是局域网 LAN

> LAN（Local Area Network）是范围相对有限、由组织者控制程度较高的网络，如宿舍、家庭、实验室或办公室网络。

LAN 不等于“必须使用某个设备”或“必须使用 Wi-Fi”。网线、Wi-Fi、交换机和无线 AP 都可以组成同一个二层 LAN。路由器的 LAN 侧通常会提供一个 IP 子网，例如：

```text
192.168.6.0/24（示例）
├── 网络地址：192.168.6.0
├── AX6：192.168.6.1
├── NAS：192.168.6.100
└── 广播地址：192.168.6.255
```

## 4.1 私有地址与 RFC1918

以下 IPv4 范围是私有地址，不能直接作为公网 Internet 上的全局可路由地址：

- `10.0.0.0/8`​：`10.0.0.0`​–`10.255.255.255`
- `172.16.0.0/12`​：`172.16.0.0`​–`172.31.255.255`
- `192.168.0.0/16`​：`192.168.0.0`​–`192.168.255.255`

因此 `192.168.6.1` 是一个私有 IP。它在宿舍 LAN 中有意义，但互联网中的其他网络不能仅凭这个地址找到它。

## 4.2 子网掩码与 CIDR

`192.168.6.0/24`​ 中的 `/24`​ 表示 IPv4 的 32 位地址中，前 24 位是网络部分，剩余 8 位是主机部分。对应掩码是 `255.255.255.0`。

```text
192.168.6.0/24
网络部分：192.168.6
主机部分：最后8位
```

- 网络地址：`192.168.6.0`
- 可用主机地址：通常为 `192.168.6.1`​–`192.168.6.254`
- 广播地址：`192.168.6.255`
- 常规可用主机数：`2^8 - 2 = 254`

注意：`192.168.6.1`​ 是一个 IP 地址；`192.168.6.0/24` 是一个网络前缀。前者标识一个接口，后者描述一组地址及其边界。

笔记：掩码&IP=192.168.6.0/24就相当于这个LAN的网络ID，掩码后的数字就相当于对应主机在这个LAN里的网络ID

# <span id="20260818174157-06yca98" class="siyuan-block-anchor" aria-hidden="true"></span>5. 私有 IP 与公网 IP

- **私有 IP**：在局部网络中重复使用，不能直接在公网全局路由。
- **公网 IP**：在公网地址体系中具有全球唯一性/可路由性，但是否能被主动访问还取决于防火墙、NAT 和服务监听。
- **Internet**：全球互联的网络集合，不等于“任何地址都能互相直连”。

“路由器有一个 IP，所以互联网可以直接访问它”通常不成立，因为这个 IP 可能是：

1. 路由器 LAN 侧私有地址，如 `192.168.6.1`；
2. 光猫或上级路由器分配的私有 WAN 地址；
3. 运营商 CGNAT 后的地址；
4. 即使是真公网 IP，入站防火墙也可能拒绝连接。

判断是否具备公网 IPv4，需要在路由器 WAN 状态中查看地址，并与外部网络看到的出口 IP 对比；还要确认中间没有 CGNAT 或多层 NAT。不要把“有 WAN 地址”直接等同于“可从公网访问”。

### 5.1 主机可以同时拥有多个 IP

一个物理主机或虚拟机可以同时拥有多个网络接口，每个接口可配置一个或多个 IP；同一接口也可能同时拥有 IPv4 和 IPv6。典型服务器可能具有：

```text
公网接口：203.0.113.10
内网接口：192.168.6.100
管理接口：10.0.0.10
```

这并不意味着“公网访问”和“内网开发”天然完全隔离。实际是否隔离，取决于路由表、监听地址、主机防火墙、网络防火墙、安全组、NAT 和服务配置：

- 服务监听 `0.0.0.0:PORT` 通常表示监听所有 IPv4 接口；
- 服务只监听 `192.168.6.100:PORT`，可限制为内网接口；
- 公网接口和内网接口可以配置不同的防火墙规则；
- 出站流量通常根据路由表选择源地址和出口，不能只看“有几个 IP”。

> 💡 **理解**：多 IP 是常见的，但“公网 IP = 一定能被访问”仍不成立，还要同时满足路由可达、防火墙放行、端口开放和服务监听。

# <span id="20260818174157-s3rda6h" class="siyuan-block-anchor" aria-hidden="true"></span>6. 什么是 Internet

> Internet 是大量自治网络通过路由器、运营商网络和交换节点互联形成的全球网络。

当宿舍设备访问 `8.8.8.8`（示例）时，数据通常经过：

```text
宿舍主机
  ↓ LAN 二层
AX6：192.168.6.1（示例）
  ↓ WAN / 上级网络
光猫或上级设备
  ↓
运营商接入网与核心网
  ↓
多个自治网络和骨干链路
  ↓
目标网络
  ↓
8.8.8.8
```

每个路由器通常只需要决定“下一跳”，不需要知道从起点到终点的完整物理路径。路由协议和运营商之间的 BGP 等机制共同维护大规模可达性。

笔记：所以宿舍设备只需要访问8.8.8.8，就相当于确认了访问的终点。然后将数据包发送给自己的网关，比如说路由器，由路由器将数据包发送给光猫或上级设备，再通过运营商接入到更大的网络中，最后就会将数据包发送给8.8.8.8（在无防火墙且已经握手成功的情况下）

# <span id="20260818174157-0fpbu6t" class="siyuan-block-anchor" aria-hidden="true"></span>7. 光猫到底是什么

> 光猫（ONT/ONU）是把运营商光纤侧的接入信号转换为用户侧以太网等接口的设备。

典型拓扑：

```text
Internet
   ↓
运营商核心/接入网络
   ↓ 光纤
光猫（ONT/ONU）
   ↓ 以太网
AX6 路由器（OpenWrt）
   ↓
交换机 / Wi-Fi
   ↓
电脑 / 手机 / NAS / Server
```

- **光猫**：完成光电/协议接入、认证或桥接/路由等运营商相关功能。
- **路由器**：连接不同 IP 网络，提供 DHCP、NAT、防火墙、Wi-Fi、路由等功能。
- **桥接模式**：光猫尽量只做接入转换，把上网认证或公网地址交给 AX6；可减少一层 NAT。
- **路由模式**：光猫自己建立一个 IP 网络并执行路由/NAT，AX6 的 WAN 处于光猫的下级网络，可能形成双重 NAT。

具体功能取决于运营商设备和配置，不能假设所有光猫都支持或允许桥接。光猫与 AX6 之间还可能有 VLAN、PPPoE、运营商认证等细节。

### 7.1 有公网 IP 的服务器如何被访问

物理服务器不一定直接连接在 Internet 上。常见情况有三种：

|部署方式|访问路径|
| -----------------------| ----------------------------------------------------------------|
|服务器直接获得公网 IP|公网路由 → 服务器网卡 → 主机防火墙 → 服务端口|
|服务器位于路由器后|公网 IP → 路由器端口映射/DNAT → 内网服务器 IP → 服务端口|
|服务器位于云平台|公网 IP 通常由云平台边缘或虚拟网卡映射，再经过安全组和实例系统|

直接公网 IP 只是让地址具备公网路由条件，仍需满足：

1. 上游路由能够到达该地址；
2. 防火墙或安全组允许入站流量；
3. 服务监听正确的接口和端口；
4. 返回流量能够沿正确路径回去。

例如服务器监听 `192.168.6.100:22`​，即使另一块网卡有公网 IP，公网访问也不能自动进入这个只绑定内网地址的服务。若服务监听 `0.0.0.0:22`，还需要主机和上游防火墙允许 TCP 22。

笔记：光猫就是一个连接互联网（虽然是运营商啥的，但本质上上层已无需考虑）与家庭内网的设备，让内网可以通过光猫去访问互联网，并让互联网无法通过光猫配置的LAN的IP直接访问内网设备。

# <span id="20260818174157-r284ymi" class="siyuan-block-anchor" aria-hidden="true"></span>8. 路由器到底是什么

> 路由器在网络层根据目标 IP 和路由表，把数据包从一个接口转发到另一个接口。

交换机主要依据 MAC 地址在同一二层网络内转发帧；路由器依据 IP 地址连接不同三层网络。现代设备可能把交换机、AP、防火墙、NAT 和路由器功能集成在一起，但概念仍应分开理解。

### 8.1 WAN 口与 LAN 口

|接口|连接方向|典型地址|主要作用|
| ------| -------------------------------| ------------------------------------------| ----------------------------------------------|
|WAN|连接上级网络、光猫或 Internet|可能是公网 IP、上级私网 IP 或 CGNAT 地址|接收来自上级网络的流量，提供外部出口|
|LAN|连接本地设备、交换机或 Wi-Fi|如 `192.168.6.1`|为本地网络提供网关、DHCP、DNS 转发和内部转发|

路由器通常为 WAN 和 LAN 配置不同的三层网络。LAN 内设备访问外部网络时，先把帧交给 LAN 口的网关；路由器查 WAN 方向的路由并转发。外部流量进入 WAN 后，默认不会直接进入 LAN，是否允许转发由防火墙、NAT 和端口映射决定。

> 💡 **理解**：路由器不是简单“把所有数据包传给光猫”；它根据目标 IP、路由表和防火墙规则决定是否从 WAN/LAN 的另一个接口转发。

```text
WAN：上级/互联网方向
   │
[路由器：三层转发、防火墙、NAT、DHCP]
   │
LAN：192.168.6.0/24（示例）
```

AX6 的 LAN IP 示例为 `192.168.6.1`。它之所以是网关，是因为宿舍 LAN 中的主机被配置为：

```text
默认网关 = 192.168.6.1（示例）
```

访问同一子网的 `192.168.6.100`​ 时，主机可以通过 ARP 直接找到目标 MAC，帧在 LAN 内发送，不必把 IP 包交给路由器转发。访问 `8.8.8.8`​ 时，目标不属于 `192.168.6.0/24`，主机按照默认路由把帧交给 AX6 的 LAN MAC，由 AX6 继续转发。

笔记：ARP（Address Resolution Protocol）是一个用于将IP地址映射到物理网络地址（MAC地址）的协议。在计算机网络中，每个设备都有一个唯一的MAC地址和IP地址，而ARP协议允许设备通过IP地址找到对应的MAC地址，以便进行通信。

当一个设备需要与另一个设备通信时：

- 首先使用ARP协议在本地网络中查找目标设备的MAC地址。

  如果目标设备的MAC地址已知，则数据包将直接发送到该地址。

  如果目标设备的MAC地址未知，则ARP协议将广播一个请求，以请求目标设备回复其MAC地址。

一旦ARP请求得到答复，设备就可以使用该MAC地址进行通信。

# <span id="20260818174157-ynpolo4" class="siyuan-block-anchor" aria-hidden="true"></span>9. 默认网关

> 默认网关是“当路由表没有更具体匹配时，主机把数据交给的下一跳路由器”。

主机可能有：

```text
192.168.6.0/24  dev eth0       # 本地直连
0.0.0.0/0       via 192.168.6.1 # 默认路由，示例
```

同网段目标直接发送；非同网段目标发送给 `192.168.6.1`。默认网关必须在本地可达的链路上，通常与主机处于同一 IP 子网。

### 9.1 子网掩码如何参与判断

主机会用自己的 IP 和子网掩码计算网络前缀，再对目标 IP 做同样的计算：

```text
本机：192.168.6.10/24 → 网络前缀 192.168.6.0
目标：192.168.6.100   → 网络前缀 192.168.6.0
结论：同一子网，直接解析目标 MAC

目标：192.168.7.100   → 网络前缀 192.168.7.0
结论：不同子网，交给默认网关
```

“在子网掩码内”更准确的说法是：本机和目标 IP 经过掩码计算后得到相同网络前缀。主机不会把数据包先发给路由器再由路由器决定同网段目标。

同网段通信通常由主机直接通过 ARP 获取目标 MAC，交换机负责转发。

# <span id="20260818174157-jun34h7" class="siyuan-block-anchor" aria-hidden="true"></span>10. 路由表

> 路由表是设备根据目标 IP 选择出口接口和下一跳的规则集合。

常见字段：

|字段|含义|
| ----------------| ---------------------------------------|
|Destination|目标网络或主机|
|Netmask/Prefix|目标范围，如 `/24`|
|Gateway|下一跳 IP；“直连”表示不需要额外网关|
|Interface|从哪个接口发出|
|Metric|同等匹配时的优先代价|

AX6 的简化路由表示例（示例，不代表当前真实输出）：

```text
Destination       Gateway       Interface
192.168.6.0/24    直连          br-lan
0.0.0.0/0         上级网关      wan
```

- `192.168.6.100`​ 匹配 `192.168.6.0/24`​，从 `br-lan` 发出。
- `8.8.8.8`​ 不匹配该直连网络，匹配 `0.0.0.0/0`​，从 `wan` 发出。

Linux/OpenWrt 中可以查看：

```bash
ip route
ip route get 192.168.6.100
ip route get 8.8.8.8
```

# <span id="20260818174157-m6h1phh" class="siyuan-block-anchor" aria-hidden="true"></span>11. 最长前缀匹配

> 当多个路由都能匹配目标地址时，选择前缀最长、最具体的路由。

一张简化路由表：

```text
10.0.0.0/8       via A # 发向10.0.0.0/8的数据包，下一步交给A，由A转发
10.147.0.0/24    via B
10.147.0.2/32    via C
```

访问 `10.147.0.2`​ 时，三个都可能匹配，但 `/32`​ 比 `/24`​ 更具体，因此走 C；访问 `10.147.0.50`​ 时走 `/24`​；其他 `10.x.x.x`​ 走 `/8`​。`0.0.0.0/0` 能匹配任何 IPv4 地址，但最不具体，所以通常只是兜底。

### 10.1 路由/route是什么

路由是“根据目标 IP 选择下一跳和出口接口”的过程；路由表是保存这些选择规则的数据结构。路由条目中的 `via` 表示“经由某个下一跳路由器”，例如：

```text
192.168.6.0/24 dev br-lan       # 目标在直连 LAN，直接从 br-lan 发出
0.0.0.0/0 via 192.168.6.1 dev eth0 # 其他目标经由网关发出
```

`via 192.168.6.1`​ 不表示数据包最终目的地是 `192.168.6.1`，而是表示当前设备先把包交给这个下一跳，由它继续路由。下一跳必须在当前设备可直接到达的链路上。

### 10.2 最长前缀匹配的直观例子

```text
笔记本：10.147.0.2
路由器 R1：10.147.0.1
路由器 R2：10.147.1.1

R1 路由表：
10.147.0.0/24  dev zt0
10.147.0.0/16  via 10.147.1.1
0.0.0.0/0      via 192.168.6.1
```

访问 `10.147.0.50`​ 时，前两条都可能匹配，但 `/24`​ 比 `/16`​ 更具体，所以直接走 `zt0`​；访问 `10.147.1.50`​ 时，匹配 `/16`​，经由 R2；访问 `8.8.8.8`​ 时，只匹配默认路由 `/0`。

最长前缀匹配可以理解为“选择覆盖目标地址的最具体网络范围”，但不是简单寻找数值最小的子网，而是比较前缀长度和目标地址是否落在该前缀内。

# <span id="20260818174157-5nqxjxd" class="siyuan-block-anchor" aria-hidden="true"></span>12. 数据包如何完成一次路由

## 12.1 宿舍笔记本访问同网段服务器

示例：笔记本 `192.168.6.10`​ 访问服务器 `192.168.6.100:22`。

1. SSH 应用产生数据。
2. TCP 封装源端口（如 `52341`​）和目标端口 `22`。
3. IP 封装源 IP `192.168.6.10`​ 和目标 IP `192.168.6.100`。
4. 主机用 `/24`​ 判断目标同属 `192.168.6.0/24`。
5. 主机通过 ARP 查询 `192.168.6.100` 的 MAC。
6. 网卡发出 Ethernet Frame：目标 MAC 是服务器 MAC。
7. 交换机根据 MAC 表把帧送往服务器端口。
8. 服务器收到后逐层解封装并回复。

## 12.2 宿舍笔记本访问互联网

```text
192.168.6.10
      ↓ 目标不在本地/24
192.168.6.1（AX6 默认网关）
      ↓ 查 WAN 路由
光猫/上级设备
      ↓
ISP
      ↓
Internet
      ↓
目标 8.8.8.8（示例）
```

每经过一个三层路由器，设备通常会：检查目标、查路由表、减少 TTL、重新计算相关校验，并用下一条链路的二层封装发送。原始 Ethernet 帧不会跨越整个 Internet；每一跳都会重新封装。IP 目标在没有 NAT 的情况下保持逻辑一致，但二层源/目标 MAC 随链路变化。

### 12.3 多层拓扑中的一次路由

```text
Laptop 192.168.6.10
  ↓ 默认网关
AX6 LAN 192.168.6.1
  ↓ AX6 WAN 100.64.12.3
运营商 CGNAT
  ↓ 公网出口 203.0.113.20
Internet
  ↓
Server 198.51.100.50:22
```

访问服务器时：

1. Laptop 判断 `198.51.100.50`​ 不属于 `192.168.6.0/24`，选择默认路由。
2. Laptop 通过 ARP 获取 AX6 LAN 接口的 MAC，并把以太网帧交给 AX6。
3. AX6 解封装二层帧，查询路由表，从 WAN 口转发。
4. 若启用 NAT，AX6 修改源 IP/端口并保存连接映射。
5. 运营商 CGNAT 可能再次修改源 IP/端口。
6. 每个后续路由器都重复“查路由、选下一跳、重新封装当前链路帧”的过程。
7. 返回流量按 NAT 状态反向转换，再沿回程路径到达 Laptop。

因此，以太网 MAC 地址不会从 Laptop 一直保持到服务器；每一跳的 MAC 会变化，而 IP 在没有 NAT 的情况下保持端到端逻辑地址。

# <span id="20260818174157-y1gcheo" class="siyuan-block-anchor" aria-hidden="true"></span>13. ARP 如何找到下一跳的 MAC

> ARP 把同一 IPv4 链路上的 IP 地址解析为 MAC 地址。

如果 `192.168.6.10`​ 要把包发给同网段 `192.168.6.100`，它广播：

```text
谁拥有 192.168.6.100？请告诉 192.168.6.10 你的MAC地址。
```

服务器单播回复自己的 MAC，笔记本缓存结果后发送帧。若目标是远端 `8.8.8.8`​，笔记本不会 ARP `8.8.8.8`​，而是 ARP 本地默认网关 `192.168.6.1` 的 MAC。

核心关系：

```text
路由表：决定 IP 包交给哪个下一跳/接口
ARP：决定这个下一跳在当前链路上的 MAC
```

查看示例：

```bash
ip neigh
arp -n                 # 某些系统仍提供
```

ARP 只解决本地链路的下一跳，不负责跨 Internet 找最终主机。

# <span id="20260818174157-exg0xmv" class="siyuan-block-anchor" aria-hidden="true"></span>14. NAT / PAT

> NAT 修改 IP 包中的地址；PAT/NAPT 进一步利用端口，让多个连接共享一个外部 IPv4。

示例（地址均为示例）：

```text
NAT前：192.168.6.10:52341 → 1.2.3.4:443
NAT后：203.0.113.20:40001 → 1.2.3.4:443
```

AX6 保存映射表：

```text
203.0.113.20:40001 ↔ 192.168.6.10:52341
```

目标服务器回复 `203.0.113.20:40001`​，AX6 查表后还原为 `192.168.6.10:52341`。这通常称为 SNAT/PAT。反方向把外部目标转换到内部服务器则是 DNAT，端口映射就是常见应用。

NAT 让多个私网设备共享公网 IPv4，但也打破了“外部直接知道内部主机地址”的直连模型，所以互联网主动访问内部服务必须依赖端口映射、连接跟踪、打洞或中继等机制。NAT 不是完整防火墙，但入站映射缺失通常会阻止未关联连接。

# <span id="20260818174157-a9iq6qh" class="siyuan-block-anchor" aria-hidden="true"></span>15. CGNAT

> CGNAT 是运营商在用户网络之外再次使用私有地址和 NAT，把多个用户共享有限的公网 IPv4。

典型结构：

```text
宿舍设备 192.168.6.10
   ↓ AX6 NAT
AX6 WAN：100.64.12.3（示例，CGNAT共享地址段）
   ↓ 运营商 CGNAT
运营商公网 IPv4：203.0.113.20（示例）
   ↓
Internet
```

`100.64.0.0/10` 常用于运营商级共享地址。若 AX6 的 WAN 地址与外部网站看到的出口地址不同，且 WAN 地址处于私有或共享地址范围，可能存在上级 NAT/CGNAT。此时你通常无法在自己的 AX6 上完成从公网到宿舍设备的端口转发，因为公网入站先被运营商设备拦截。

# <span id="20260818174157-x3xx91x" class="siyuan-block-anchor" aria-hidden="true"></span>16. 为什么远程访问家庭网络这么麻烦

传统方案可能需要：公网 IPv4、DDNS、光猫桥接、端口转发、防火墙放行、服务监听和证书。若有双重 NAT 或 CGNAT，端口转发可能无法贯通。

```text
实验室 Laptop ──Internet──> 宿舍公网入口
                               ↓
                          CGNAT/光猫/AX6
                               ↓
                         NAS 192.168.6.100
```

问题本质是：两个位于不同网络、可能都在 NAT 后面的节点，如何建立可达路径，并且保证回程和访问控制正确。

# <span id="20260818174157-myplelh" class="siyuan-block-anchor" aria-hidden="true"></span>17. VPN

> VPN 是在不可信或不直接相连的底层网络上，建立逻辑连接，通常还提供加密和身份认证。

VPN 可以是站点到站点，也可以是客户端到站点。它不等于代理：

|概念|主要改变|
| -------| -------------------------------------------------------|
|VPN|通常改变主机的路由路径，并在虚拟接口/隧道中承载 IP 包|
|Proxy|通常只代理某个应用协议或连接|

VPN 的关键组成是端点、虚拟接口、隧道、密钥/身份和路由。是否全流量经过 VPN，取决于路由配置。

# <span id="20260818174157-sd81avr" class="siyuan-block-anchor" aria-hidden="true"></span>18. Overlay Network

> Overlay 是建立在 Underlay 之上的逻辑网络；Underlay 提供真实 IP 连通性，Overlay 在其上封装自己的数据包。

```text
Underlay：宿舍 Internet ───── ISP ───── 实验室 Internet
              ↑                         ↑
              │                         │
Overlay：   AX6 ZT接口 ═══ 加密/封装 ═══ Laptop ZT接口
            10.147.0.1                 10.147.0.2（示例）
```

Overlay 没有创造新的光纤或物理线路。它通过虚拟网卡和隧道，把一个逻辑网络叠加在现有 Internet 上。底层仍受 NAT、防火墙、丢包和带宽影响。

# <span id="20260818174157-o7sdef7" class="siyuan-block-anchor" aria-hidden="true"></span>19. ZeroTier

> ZeroTier 是一种基于虚拟网络接口和 Overlay 的组网软件，使加入同一 Network 的节点可以使用虚拟地址互通，并通过控制平面、点对点连接、NAT traversal 或 relay 建立数据路径。

关键概念：

- **Network**：一个逻辑虚拟网络，有 Network ID 和成员策略。
- **Node/Peer**：加入网络的设备或其 ZeroTier 节点。
- **Controller**：负责网络成员认证、地址和网络配置分发；托管网络通常通过 ZeroTier Central 管理。
- **Managed IP**：控制器分配给节点的虚拟 IP。
- **Managed Route**：向成员下发的目标网络路由。
- **NAT traversal**：尝试穿越两端 NAT 建立直连。
- **Relay**：直连失败时通过中继转发，性能和延迟可能不同。

ZeroTier 并不是魔法 VPN：它仍依赖底层 Internet，仍要经过本机路由、虚拟接口、隧道、对端节点和对端路由/防火墙。

# <span id="20260818174157-zi8q6sg" class="siyuan-block-anchor" aria-hidden="true"></span>20. ZeroTier 的虚拟网络模型

物理网络：

```text
宿舍 Internet                         实验室 Internet
     │                                      │
     └────────────── Underlay ─────────────┘
```

ZeroTier 网络：

```text
10.147.0.0/24（示例）
AX6：10.147.0.1  ═══ ZeroTier Overlay ═══  Laptop：10.147.0.2
```

`10.147.0.2`​ 不是笔记本当前 Wi-Fi 网卡的地址，也不是宿舍 LAN 地址；它属于 ZeroTier 虚拟接口。`192.168.6.100` 仍属于宿舍 LAN。要访问后者，必须额外存在“宿舍 LAN 经 AX6 到达”的路由和转发条件。

# <span id="20260818174157-agl7yec" class="siyuan-block-anchor" aria-hidden="true"></span>21. 我的宿舍网络设计

```text
                         Internet
```

# <span id="20260818174157-qk3mxvh" class="siyuan-block-anchor" aria-hidden="true"></span>22. ZeroTier Managed Routes

要让 ZeroTier 成员访问宿舍 LAN，需要下发（示例）：

```text
Destination: 192.168.6.0/24
Via:         10.147.0.1
```

含义是：

> 目标属于 `192.168.6.0/24`​ 时，ZeroTier 成员把下一跳交给 `10.147.0.1`。

访问过程：

```text
Laptop 10.147.0.2
   ↓ 查询本机路由表
192.168.6.0/24 via 10.147.0.1
   ↓
ZeroTier 虚拟接口/Overlay
   ↓
AX6 ZeroTier 接口 10.147.0.1
   ↓ OpenWrt 路由与防火墙
LAN 192.168.6.0/24
   ↓
NAS 192.168.6.100
```

Managed Route 只解决“笔记本把去宿舍 LAN 的包交给谁”。它不自动开启 AX6 的 IP forwarding，不自动放行防火墙，也不自动解决 NAS 的回程路由。

# <span id="20260818174157-hi2olsl" class="siyuan-block-anchor" aria-hidden="true"></span>23. OpenWrt 作为 ZeroTier Gateway

逻辑路径：

```text
ZeroTier interface
       ↓
OpenWrt IP forwarding
       ↓
Firewall：ZeroTier zone → LAN zone
       ↓
192.168.6.0/24
```

需要分别确认：

1. ZeroTier 服务已运行，AX6 已加入并被授权。
2. AX6 获得 ZeroTier 虚拟地址。
3. AX6 内核允许从 ZeroTier 接口转发到 LAN。
4. OpenWrt 防火墙允许对应 zone 的 forwarding 和必要服务。
5. LAN 设备能够把回复发回 ZeroTier 网络，或 AX6 对该流量做 NAT。

“能 ping AX6 的 `10.147.0.1`​”只证明 ZeroTier 节点本身可达；不能证明 AX6 已经把 `192.168.6.0/24` 转发出去。

OpenWrt 版本可能使用不同的 firewall4/nftables 或旧版 firewall3/iptables 管理方式，软件包名、配置界面和命令可能不同。以下命令仅作为核对方向，不应视为所有版本通用：

```bash
ip addr
ip route
ip rule
service zerotier status
logread | grep -i zerotier
```

具体 ZeroTier OpenWrt 安装和防火墙配置，应以当前 OpenWrt 版本及 ZeroTier 官方文档为准。不要直接复制未知版本教程中的 `iptables` 命令到生产路由器。

# <span id="20260818174157-v6rjkko" class="siyuan-block-anchor" aria-hidden="true"></span>24. 回程路由

这是完整连通性的关键。

```text
Laptop 10.147.0.2
      ↓ 请求
AX6 10.147.0.1 → NAS 192.168.6.100
      ↑ 回复
NAS 如何到达 10.147.0.2？
```

- ZeroTier Network ID 不是完整秘密，但成员授权和访问策略必须严格控制。
- 不要把整个宿舍 LAN 无条件暴露给所有 ZeroTier 成员。

- NAT 不是安全边界的替代品；Overlay 网络也不是自动可信网络。

```text
  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓
```

# <span id="20260818174157-yhfsjbo" class="siyuan-block-anchor" aria-hidden="true"></span>31. 最终心智模型

遇到任何网络问题，都按这条链条问自己：

1. **应用**：我要访问哪个服务和端口？
2. **传输层**：是 TCP 还是 UDP？目标端口是否监听？
3. **IP层**：源 IP、目标 IP 属于哪个网络？
4. **路由**：本机选择了哪条最长前缀路由？下一跳是谁？
5. **ARP/邻居**：当前链路上下一跳的 MAC 是否已解析？
6. **二层**：帧是否离开正确接口？交换机/AP 是否转发？
7. **NAT**：是否改变了地址/端口？映射和回包是否存在？
8. **防火墙**：每一跳是否允许该方向、协议和端口？
9. **回程**：目标设备回复时，是否知道回到源地址的路径？
10. **Overlay**：ZeroTier 只是提供了哪一段虚拟链路？剩余路由和防火墙是否完成？

因此，“我人在实验室却能访问宿舍 `192.168.6.100`​”的完整答案是：笔记本通过 ZeroTier 虚拟接口获得到 `192.168.6.0/24`​ 的路由，把数据封装进 Overlay，经底层 Internet 到达 AX6；AX6 作为 `10.147.0.1` 网关执行 IP 转发和防火墙放行，再通过宿舍 LAN 的二层机制把包送到 NAS；NAS 的回复则依据静态回程路由或 AX6 的 NAT 映射返回。

# 33. 为什么用 ZeroTier 而不是直接通过互联网访问设备？

> 直接公网访问在宿舍/家庭环境通常不可行：出口往往没有可主动入站的公网 IPv4，还存在 CGNAT、多层 NAT 和入站防火墙。

- **公网 IPv4 稀缺**：运营商普遍使用 CGNAT，家庭无法获得可被公网主动访问的地址，端口映射可能无法贯通。
- **传统链路太长**：公网 IP + DDNS + 光猫桥接 + 端口转发 + 防火墙放行 + 证书，任一环节失效整个方案就失败。
- **ZeroTier 绕过瓶颈**：通过 P2P 直连（NAT 打洞）或中继，在任何能上网的地方建立加密虚拟链路，**不需要公网 IP、不需要开放任何入站端口**。
- **暴露面更小**：只在虚拟网络内授权自己的设备，不向公网开放端口，攻击面小得多。
- **多设备统一管理**：笔记本、手机、服务器在同一虚拟网络内互访，与物理位置无关。

# 34. 网络适配器是什么？

> 网络适配器（网卡）是主机接入网络的硬件或虚拟接口，每个接口可拥有独立的 IP、MAC 和路由。

- **物理适配器**：Ethernet 网卡、Wi-Fi 网卡（平时可能同时存在多个）。
- **虚拟适配器**：ZeroTier 虚拟网卡、VPN 隧道接口、Loopback（`127.0.0.1`）。
- 一台主机可以同时拥有多个适配器：例如笔记本既有物理网卡（在家 `192.168.6.x`​），也有 ZeroTier 虚拟网卡（`192.168.195.2`）。
- 系统根据路由表和接口 Metric 决定从哪个适配器发包——这正是"在家走本地网卡、在外走 ZeroTier"的实现基础。

# 35. 知识点：192.168.6.0/24 与 192.168.6.1/24 的区别

> `192.168.6.0/24`​ 描述一个**网络范围**；`192.168.6.1/24`​ 描述某台设备的**具体 IP 及其子网掩码**。

- `192.168.6.0/24`​：网络前缀，代表 `192.168.6.0`​～`192.168.6.255`​ 整个网络；其中 `.0`​ 是网络地址、`.255` 是广播地址、可用主机地址 254 个。
- `192.168.6.1/24`​：某个接口的 IP 地址 + 掩码，掩码 `255.255.255.0`​ 表明它属于 `192.168.6.0/24` 这个网络。
- 二者关系：路由表里写目标是 `192.168.6.0/24`​（范围），设备接口上配置的是 `192.168.6.1/24`（身份）。一个是"整个网段"，一个是"网段里的一台设备"。

# 36. 部署目标：MC 服务器与 RK3588 NAS 网盘

> 当前 ZeroTier 组网要访问的核心服务，是宿舍内的 **MC 物理服务器**和 **RK3588 开发板控制的 NAS 网盘**。

## 36.1 目标设备

- **MC 物理服务器**：宿舍内已架构好的独立物理服务器，运行 Minecraft 服务端。
- **RK3588 NAS 网盘**：由 Rockchip RK3588 开发板搭成的 NAS，负责网盘、数据存储。

笔记本/手机通过 ZeroTier 加入网络后，即可像在家一样访问这些设备的局域网地址（`192.168.6.0/24` 网段内）。

## 36.2 让其他玩家通过 ZeroTier 游玩 MC 服务器

1. 玩家安装 ZeroTier 客户端（Windows/macOS/Linux/手机均可），加入本网络 `[已隐藏 Network ID]`。
2. 管理员在 ZeroTier Central 中**授权**该玩家的设备，并确认其获得 `192.168.195.0/24` 网段内的虚拟地址。
3. 为玩家下发 Managed Route：`192.168.6.0/24 via 192.168.195.4`（或让玩家手动添加静态路由）。
4. 玩家在 Minecraft 中添加服务器，地址填 MC 服务器的局域网 IP（如 `192.168.6.x`​），端口 `25565`。
5. 前提检查：MC 服务端需监听 `0.0.0.0`​（或对应 LAN 接口），OpenWrt 防火墙放行 ZeroTier→LAN 的 `25565` 端口流量。
6. 注意事项：NAT 方案下玩家流量到达 MC 服务器时来源显示为 `192.168.6.1`​（网关）；若需区分玩家真实 IP（如白名单按 IP 校验），需改用纯路由方案并为 `192.168.195.0/24` 配置回程路由。
