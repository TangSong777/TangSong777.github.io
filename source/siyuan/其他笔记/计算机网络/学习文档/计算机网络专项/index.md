## 一、网络通信的分层模型

> 计算机网络是多个节点通过链路连接，并按照共同协议交换数据的系统；一次通信是多层协议协作的结果，不是"电脑直接连电脑"。

### 1.1 一次通信的数据封装

```
应用数据：SSH 请求
   ↓
TCP：源端口、目标端口、可靠传输
   ↓
IP：源IP、目标IP、跨网络寻址
   ↓
Ethernet/Wi-Fi：本链路上的源MAC、目标MAC
   ↓
物理链路
```

### 1.2 三种地址的分工

|地址|解决的问题|作用范围|示例|
| ----------| ------------------------| ------------------| -----------------------|
|MAC 地址|本地链路上交给哪块网卡|当前二层链路|`aa:bb:cc:dd:ee:ff`|
|IP 地址|跨网络找到目标主机|全局（逻辑寻址）|`192.168.6.100`|
|端口|主机上哪个服务|单台主机内|`22`​（SSH）、`25565`（MC）|

> 类比：IP 是楼栋地址，MAC 是当前小区内的具体收件设备，端口是设备上的房间/服务。

### 1.3 二层网络与三层网络

> 二层（L2）网络工作于数据链路层：设备通过 **MAC 地址**在本地链路内直接通信；三层（L3）网络工作于网络层：通过 **IP 地址**跨网络路由。

- 分层对应：

|层|名称|寻址依据|转发设备|转发单位|
| -----------| ------------| ----------| -------------------| -------------|
|二层 (L2)|数据链路层|MAC 地址|交换机 / 无线 AP|帧 (Frame)|
|三层 (L3)|网络层|IP 地址|路由器 / 三层网关|包 (Packet)|

- 通俗理解：

```
二层网络 = 同一"楼层/小区"内直接喊话
  —— MAC 找具体邻居，交换机按 MAC 转发，不需要路由器
三层网络 = 跨小区送信
  —— IP 写目的地，路由器逐跳决定"下一站往哪走"
```

- 关键识别（结合本项目）：

  - **同网段**（`192.168.6.x`​ ↔ `192.168.6.x`）：通常在同一二层网络内，靠交换机 + ARP 转发帧，路由器不参与；
  - **跨网段**（`192.168.6.x` → 其他网段/公网）：必须经过三层处理（路由器/默认网关）；
  - 一句话：**二层解决"这一跳交给谁"，三层解决"整条路往哪走"** ；ARP 是连接两者的桥（把目标 IP 解析为本地的 MAC，见第五章）。
- 实际设备：家用路由器内部**同时**含二层交换（LAN 口之间）与三层路由（LAN↔WAN）功能——呼应 7.5 "路由器在 LAN 中的两种角色"。

## 二、IP 地址、子网与 CIDR

> IP 地址标识接口，CIDR 用"前缀长度"简洁描述一个网络的地址范围。

### 2.1 私有地址（RFC1918）

|范围|CIDR|
| ------------| ------|
|`10.0.0.0`​ – `10.255.255.255`|`10.0.0.0/8`|
|`172.16.0.0`​ – `172.31.255.255`|`172.16.0.0/12`|
|`192.168.0.0`​ – `192.168.255.255`|`192.168.0.0/16`|

私有地址不能直接作为公网全局可路由地址；`192.168.6.1` 是私有 IP，在宿舍 LAN 中有意义，但互联网中的其他网络不能仅凭这个地址找到它。

> 是的——CIDR（Classless Inter-Domain Routing，无类别域间路由）就是用"IP 前缀 + 前缀长度"描述一个**网络范围**的标准写法：`192.168.6.0/24` 表示"网络前缀是 192.168.6.0，前 24 位是网络部分"。

- 它取代了早期"分类地址（A/B/C 类）+ 子网掩码"的僵硬划分，网络可按需任意切分（`/8`​ 到 `/32`）。
- 写法等价转换：

|CIDR 写法|等价子网掩码|主机部分位数|可用主机数|
| ---------------| --------------| --------------| ------------|
|`/24`​（如 `192.168.6.0/24`）|`255.255.255.0`|8 位|2⁸−2=254|
|`/16`​（如 `10.0.0.0/16`）|`255.255.0.0`|16 位|65534|
|`/8`​（如 `10.0.0.0/8`）|`255.0.0.0`|24 位|约 1677 万|

- 一句话记忆：`192.168.6.0/24`​ = "范围 + 边界"；同样的写法也能用于描述单台设备，如 `192.168.6.1/24` 表示"这台设备的 IP 是 192.168.6.1，子网掩码 255.255.255.0"（见 2.3）。

### 2.2 /24 的含义

`192.168.6.0/24`​：前 24 位是网络部分，剩余 8 位是主机部分，对应掩码 `255.255.255.0`。

- 网络地址：`192.168.6.0`
- 可用主机：`192.168.6.1`​ – `192.168.6.254`​（共 `2^8-2=254` 个）
- 广播地址：`192.168.6.255`

### 2.3 网络地址 vs 设备地址（易错点）

- `192.168.6.0/24`​：描述**整个网络**的范围与边界。
- `192.168.6.1/24`​：描述**一台设备**的 IP 及其掩码。
- 路由表里目标是 `.0/24`​（范围），接口上配置的是 `.1/24`（身份）。

### 2.4 判断是否同网段

主机用自己的 IP 和掩码计算网络前缀，再对目标 IP 做同样计算：

```
本机：192.168.6.10/24 → 网络前缀 192.168.6.0
目标：192.168.6.100   → 网络前缀 192.168.6.0
结论：同一子网，直接 ARP 解析目标 MAC

目标：192.168.7.100   → 网络前缀 192.168.7.0
结论：不同子网，交给默认网关
```

## 三、局域网 LAN 与默认网关

> LAN 是范围相对有限、由组织者控制程度较高的网络（宿舍、家庭、实验室）；默认网关是"路由表没有更具体匹配时，主机把数据交给的下一跳路由器"。

- LAN 不等于某个设备或 Wi-Fi：网线、交换机、无线 AP 可组成同一个二层 LAN。
- 默认网关必须与本机在同一 IP 子网内、本地可达。
- 同网段目标直接发送；非同网段目标发送给默认网关。

- LAN 常见形态示例（家庭/宿舍，直接沿用本项目真实网段）：

  ```
  192.168.6.0/24（示例）
  ├── 网络地址：192.168.6.0
  ├── AX6：192.168.6.1
  ├── NAS：192.168.6.100
  └── 广播地址：192.168.6.255
  ```
- 广播地址（`.255`）的用途：ARP 请求、DHCP 发现等"面向全网络"的帧会发往它。

## 四、路由与路由表

> 路由是"根据目标 IP 选择下一跳和出口接口"的过程；路由表是保存这些选择规则的数据结构。

### 4.1 路由表常见字段

|字段|含义|
| ------------------| -----------------------------------|
|Destination|目标网络或主机|
|Netmask / Prefix|目标范围，如 `/24`|
|Gateway|下一跳 IP；"直连"表示不经过路由器|
|Interface|从哪个接口发出|

`via 192.168.6.1`​ 不表示数据包最终目的地是 `192.168.6.1`，而是先交给这个下一跳，由它继续路由。

### 4.2 最长前缀匹配

> 当多个路由都能匹配目标地址时，选择前缀最长、最具体的路由。

```
10.0.0.0/8       via A
10.147.0.0/24    via B
10.147.0.2/32    via C
```

- 访问 `10.147.0.2`​ → 走 C（`/32` 最具体）
- 访问 `10.147.0.50`​ → 走 B（`/24`）
- 访问其他 `10.x.x.x`​ → 走 A；都不匹配才走默认路由 `0.0.0.0/0`

### 4.2.1 via 下一跳与直观例子

- `via 192.168.6.1`​ 表示"把包交给这个下一跳，由它继续路由"，不是最终目的地；**下一跳必须位于当前设备可直接到达的链路上**。

直观例子（R1 路由表）：

```
笔记本：10.147.0.2
R1 路由表：
10.147.0.0/24  dev zt0
10.147.0.0/16  via 10.147.1.1
0.0.0.0/0      via 192.168.6.1
```

- 访问 `10.147.0.50`​ → `/24`​ 比 `/16`​ 更具体，走 `zt0`；
- 访问 `10.147.1.50`​ → 匹配 `/16`​，经 R2（`via 10.147.1.1`）；
- 访问 `8.8.8.8`​ → 只匹配默认 `/0`。

### 4.2.2 同网段与跨网段的完整过程

同网段（`192.168.6.10`​ → `192.168.6.100:22`）：

1. SSH 应用产生数据 → TCP 封装源端口（如 `52341`​）与目标端口 `22` → IP 封装源/目标 IP；
2. 主机用 `/24`​ 判断目标同属 `192.168.6.0/24`；
3. ARP 查询 `.100` 的 MAC → 网卡发出帧（目标 MAC = 服务器 MAC）→ 交换机按 MAC 表转发；
4. 服务器逐层解封装并回复。

跨网段（访问 `8.8.8.8`​）：目标不属于本地 `/24`​ → 查默认路由 → 帧交给 `192.168.6.1`​（AX6）→ AX6 查 WAN 路由逐跳转发；**每跳都做四件事**：查路由表、TTL 减 1、重新计算校验、用新链路的 MAC 重新封装。

### 4.3 Windows 的双重判据：最长匹配 + Metric

Windows 路由选择顺序：先最长前缀匹配，再比 Metric（越小越优先）。这正是"在家走本地 LAN、在外走 ZeroTier"自动切换的实现基础（ZeroTier 接口与静态路由 Metric 设 5000，物理网卡 Metric 低）。

### 4.4 数据包如何完成一次路由（多层拓扑实例）

> 一次跨网段通信会逐跳处理：每跳路由器只查自己的路由表决定"下一跳"，并用下一跳所在链路重新封装二层帧。

拓扑（示例，含多层 NAT）：

```
Laptop 192.168.6.10
  │ 默认网关
AX6 LAN 192.168.6.1
  │ AX6 WAN 100.64.12.3
运营商 CGNAT 203.0.113.20
  │
Internet → Server 198.51.100.50:22
```

访问远程服务器的逐跳动作：

1. Laptop 判断 `198.51.100.50`​ 不属于 `192.168.6.0/24`​ → 查默认路由 → 下一跳 `192.168.6.1`；
2. Laptop 用 ARP 找 AX6 LAN 口的 MAC，把 IP 包封装进以太网帧交给 AX6；
3. AX6 解封装二层帧，查路由表 → 从 WAN 口发出（做一层 NAT：源地址 `192.168.6.10`​ → `100.64.12.3`）；
4. 运营商 CGNAT 再转一层（源 → `203.0.113.20`）；
5. 每一跳路由器完成四件事：检查目标、查路由表、TTL 减 1、重新计算校验、用**新链路的 MAC** 重新封装。

关键理解：**MAC 地址不会从 Laptop 一直保持到 Server**（每一跳都变化）；**IP 在无 NAT 时保持端到端逻辑地址**（有 NAT 则每层 NAT 修改一次源地址）。

## 五、ARP：找到下一跳的 MAC

> ARP 把同一 IPv4 链路上的 IP 地址解析为 MAC 地址，只负责"当前链路下一跳"，不负责跨 Internet 找最终主机。

- 同网段目标：ARP 目标设备的 IP。
- 远端目标：ARP 本地默认网关的 IP（不是远端 IP）。
- 关系：**路由表决定 IP 包交给哪个下一跳/接口；ARP 决定这个下一跳在当前链路上的 MAC**。

### 5.1 ARP 工作过程与命令

广播示例：

```
谁拥有 192.168.6.100？请告诉 192.168.6.10 你的MAC地址。
```

- 目标设备**单播回复自己的 MAC**，本机缓存该映射，后续直接发送。
- 访问远端（如 `8.8.8.8`​）时，本机 ARP 的是**默认网关**（`192.168.6.1`​）的 MAC，而不会 ARP `8.8.8.8`。
- 查看命令：

```bash
ip neigh   # 查看邻居缓存（ARP 表）
arp -n     # 某些系统仍提供
```

- ARP 只解决"当前链路的下一跳"，不负责跨 Internet 找最终主机（与路由表配合：**路由表决定把 IP 包交给哪个下一跳/接口，ARP 决定这个下一跳在当前链路上的 MAC**）。

## 六、NAT / PAT / CGNAT

> NAT 修改 IP 包中的地址；PAT/NAPT 进一步利用端口，让多个连接共享一个外部 IPv4。

### 6.1 基本流程

```
NAT前：192.168.6.10:52341 → 1.2.3.4:443
NAT后：203.0.113.20:40001 → 1.2.3.4:443
```

路由器保存映射表，回包时反向还原。修改源地址为 SNAT，反方向把外部目标转换到内部服务器为 DNAT（端口映射即 DNAT 的一种）。

### 6.1.1 NAT 映射表与连接跟踪

- AX6 保存映射表：

```
203.0.113.20:40001 ↔ 192.168.6.10:52341
```

- 目标服务器回复 `203.0.113.20:40001`​，AX6 查表还原为 `192.168.6.10:52341`——这就是 SNAT/PAT；反方向把外部目标转换到内部服务器为 DNAT（端口映射就是 DNAT 的常见应用）。
- **NAT 不是完整防火墙**，但**入站映射缺失通常会阻止未关联连接**：外部主动发起的连接若无对应映射条目，无法进入内网。
- 互联网主动访问内部服务，必须依赖端口映射、连接跟踪、打洞或中继等机制。

### 6.2 为什么需要 NAT

让多个私网设备共享一个公网 IPv4；代价是打破了外部直连内部主机的模型，互联网主动访问内部服务必须依赖端口映射、连接跟踪等手段。

### 6.3 CGNAT 与远程访问困境

- CGNAT 是运营商在用户网络之外再次使用私有地址和 NAT（`100.64.0.0/10` 常用于运营商级共享地址）。
- 判断方法：路由器 WAN 地址与外部网站看到的出口 IP 不同，且 WAN 处于私有/共享段 → 可能存在 CGNAT。
- 传统远程访问（公网 IPv4 + DDNS + 光猫桥接 + 端口转发 + 证书）在 CGNAT 下可能无法贯通，这正是需要 Overlay 网络（ZeroTier）的核心原因。

### 6.4 CGNAT 工作机制详解（补充）

> CGNAT 是"运营商版本的 NAT"：家里那层 NAT 之外，运营商再装一道闸，让海量用户共共享极少量的公网 IPv4。

- 层级示意（与我们的宿舍环境一致）：

```
家庭设备 192.168.6.10
   ↓ 家里的 NAT（AX6）
AX6 WAN：100.64.12.3（运营商分配的共享地址）
   ↓ 运营商 CGNAT
运营商出口公网 IPv4：203.0.113.20（大量用户共用）
   ↓
Internet
```

- **为什么存在**：公网 IPv4 总数有限（约 42 亿），运营商让几十万户共用少量出口 IP，节约公网地址的"最后一招"。
- **关键特性**：

  - 共享地址段 `100.64.0.0/10`（RFC 6598），介于私网与公网之间，公网不可路由；
  - 你的 WAN 地址是"小区公共门牌"：出口 IP 大家轮流用，外部看到的地址不固定；
  - NAT 映射表维护在运营商设备上，普通用户**无法配置、无法查看 → 端口映射必然失效**。
- **对远程访问的影响**：

  - 在家配端口映射到 AX6 → 运营商 CGNAT 不认识你的出口地址 → 外网流量进不来；
  - P2P（BT、ZeroTier 点对点）依赖 NAT 打洞，打洞失败退化为中继。
- **类比**：CGNAT 像小区物业统一收发快递——快递只到物业（100.64.x.x），物业再转给各家；你想让外面直接寄到家里（端口映射），物业不配合就做不到。
- **判断方法**：对比"路由器 WAN 页显示的地址"与"外部网站看到的出口 IP"（如访问 ipinfo.io 显示的公网 IP）；若两者不同且 WAN 处于 `100.64.0.0/10`（或其它私有段）→ 存在上级 CGNAT/多层 NAT。
- **结论**：这正是 ZeroTier 等 Overlay 工具的价值所在——通过打洞或中继绕开 CGNAT 直接连通（详见 [ZeroTier专项](/siyuan/其他笔记/计算机网络/学习文档/ZeroTier专项/)）。

### 6.5 为什么远程访问家庭网络这么麻烦（完整链路）

> 传统远程访问方案要打通一整条"可达链"，任一环断裂都失败；CGNAT 与多层 NAT 常让端口转发直接失效。

传统链路（从外到内）：

```
公网 IPv4（必须可入站）
  ↓ DDNS（域名指向可能变化的 IP）
光猫桥接（把公网 IP 透传/桥接给路由器）
  ↓ 端口转发（把外部端口 DNAT 到内网服务）
防火墙放行（对应入站端口）
  ↓ 服务监听正确接口 + HTTPS 证书
```

需要**同时满足**：公网 IPv4、DDNS、光猫桥接、端口转发、防火墙放行、服务监听、证书——任一环失效（尤其是 CGNAT/双重 NAT），方案就全盘皆输。

- **问题本质**：两个都位于 NAT 后面的节点，如何建立可达路径，并保证回程与访问控制正确。
- **这正是 ZeroTier 等 Overlay 工具的切入点**：在"底层不可达"之上建立"逻辑可达"，绕开整条传统链路（详见 [ZeroTier专项](/siyuan/其他笔记/计算机网络/学习文档/ZeroTier专项/)）。

## 七、Internet、光猫与路由器

> Internet 是大量自治网络通过路由器、运营商网络和交换节点互联形成的全球网络；路由器在网络层根据目标 IP 和路由表把数据包从一个接口转发到另一个接口。

### 7.1 下一跳转发

每个路由器通常只需决定"下一跳"，不需要知道从起点到终点的完整物理路径；以太网 MAC 地址不会跨链路保持，每一跳都会变化，而 IP（无 NAT 时）保持端到端逻辑地址。

### 7.2 光猫与路由器的分工

|设备|职责|
| --------------| -------------------------------------------------------|
|光猫 ONT/ONU|光电/协议接入、认证、桥接或路由等运营商相关功能|
|路由器|连接不同 IP 网络，提供 DHCP、NAT、防火墙、Wi-Fi、路由|

路由器不是简单"把所有数据包传给光猫"，它根据目标 IP、路由表和防火墙规则决定是否转发。

### 7.2.0 光猫的桥接模式与路由模式

- **桥接模式**：光猫只做光电/协议接入，把上网认证（PPPoE 拨号）或公网地址**透传**给 AX6，减少一层 NAT；
- **路由模式**：光猫自己建立 IP 网络并执行路由/NAT，AX6 的 WAN 处于光猫的下级网络，可能形成**双重 NAT**（远程访问更困难，呼应 6.5）。
- 具体支持哪些模式取决于运营商设备与配置，**不能假设所有光猫都允许桥接**；光猫与 AX6 之间还可能有 VLAN、PPPoE、运营商认证等细节。

### 7.2.1 WAN 口与 LAN 口

|接口|连接方向|典型地址|主要作用|
| ------| -----------------------| ------------------| ------------------------------------|
|WAN|上级网络 / 互联网方向|公网地址或 `100.64.x.x` 等|外出流量出口、PPPoE 拨号、上级路由|
|LAN|内部设备|`192.168.6.0/24`|DHCP 分发、二层交换、内部设备互联|

- 路由器为 WAN 与 LAN 配置不同的三层网络；LAN 内设备外出时，先把帧交给 LAN 口网关，路由器查 WAN 方向的路由并转发；外部流量进入 WAN 后，按路由/防火墙规则决定是否到达内网。
- **光猫细节**：光猫（ONT/ONU）负责光电信号转换、运营商认证（PPPoE 拨号）、桥接/路由模式；具体功能取决于运营商配置，**不能假设所有光猫都支持或允许桥接**；光猫与路由器之间还可能有 VLAN、PPPoE 认证等细节，配置问题时先查光猫模式再接路由器 WAN。

### 7.2.2 私有 vs 公网 IP 的判断（补充）

- 判断是否具备可入站公网 IPv4：看**路由器 WAN 状态中的地址**，再与**外部网站看到的出口 IP**（如访问 ipinfo.io 显示的公网 IP）对比；两者不同，且 WAN 处于 `100.64.0.0/10`​、`10.x`​、`172.16.x`​、`192.168.x` 之一 → 存在 CGNAT 或上级 NAT。
- 不要把"路由器 WAN 页显示有地址"等同于"公网可入站"——那个地址可能是私有/共享段（呼应 7.3）。

### 7.3 有公网 IP 能被访问吗？

"路由器有一个 IP，所以互联网可以直接访问它"通常不成立，因为：可能是 LAN 侧私有地址、上级分配的私有 WAN 地址、CGNAT 后地址，或入站防火墙拦截。直接公网 IP 只是让地址具备公网路由条件，还需：上游路由可达、防火墙放行、服务监听正确接口端口、回程路径正确。服务监听 `0.0.0.0:PORT` = 监听所有接口；只监听内网 IP 则公网无法访问。

### 7.4 有公网 IPv6 能被访问吗？（延伸）

> 能，但"拥有公网 IPv6"只是消除了"没有公网地址"这个最大障碍；能否被访问仍取决于防火墙、监听和链路条件——结论与 7.3 的 IPv4 部分一致，只有"地址可得性"这一环不同。

- **IPv6 不引入 NAT**：服务器可直接获得全局单播地址（GUA，`2000::/3`），公网无须端口映射即可路由到它——这是与"看运气拿公网 IPv4 / 被 CGNAT"的根本区别。
- **但"地址可达" ≠ "服务可访问"** ，仍需同时满足：

  1. **路由器允许入站**：宿舍/机房路由器的 IPv6 入站策略不得拦截该地址的目标端口；
  2. **主机防火墙放行**：Windows/Linux 防火墙默认可能拦截入站 IPv6 流量；
  3. **服务监听正确**：监听 `::`​（所有 IPv6 接口）或对应 GUA；只监听 `127.0.0.1`/内网 IPv4 则 IPv6 不可达；
  4. **地址稳定**：SLAAC 隐私扩展会产生临时地址，对外需固定一个 GUA（或在路由器配 DHCPv6 固定分配）。
- **相比 IPv4 更简单的一环——回程**：无 NAT 时源地址就是真实 GUA，返回流量沿同一路径回来，不需要 NAT 映射表查转换；破坏回程的主要是防火墙策略而非地址机制。
- 验证：

```bash
ip -6 addr                          # 本机是否持有 2000::/3 的 GUA
curl -6 https://6.ipw.cn            # 从服务器确认出口是公网 IPv6
```

- 对端（手机蜂窝网络一般有 IPv6）直接 `ping6 服务器GUA`​，或浏览器访问 `http://[服务器GUA]:80`（IPv6 地址用方括号包裹）。
- **关联本项目**：Rock5B+ 正是此场景——宿舍有 IPv6 公网，博客的"IPv6 直连"方案就依赖"防火墙放行 + 监听 `::` + 固定 GUA"这三条（见博客部署学习方案第六章）。

### 7.5 路由器在 LAN 中的两种角色（网关 / 交换机）

> 路由器在局域网内同时扮演逻辑上的"网关"（三层路由）与物理上的"二层交换"两重身份，理解这两者区分是看懂家庭网络的关键。

- **角色一：网关（三层，路由决策）**

  - LAN 内设备把"去外部网络"的数据包默认交给它（默认网关 `192.168.6.1`）；
  - 它连接 LAN 与 WAN 两个不同网段，负责转发、NAT、防火墙。
- **角色二：交换机（二层，MAC 帧转发）**

  - 路由器 LAN 口的多个设备之间，本质是一个二层交换网络：同网段设备通信靠 ARP + MAC 交换，**不经过路由决策**；
  - 这就是为什么 `192.168.6.2 → 192.168.6.5` 是直接交换帧，路由器"不插手"。
- 一句话区分：

```
跨网段（192.168.6.x → 公网/其它网段）：走「网关」功能（路由 + NAT）
同网段（192.168.6.x → 192.168.6.x）：走「交换机」功能（二层 MAC 转发）
```

- 现代家用路由器 = 路由器 + 交换机 + 无线 AP + DHCP + 防火墙一体化设备（呼应 7.2 的光猫/路由器分工表）。

## 八、VPN 与 Overlay Network

> VPN 是在不可信或不直接相连的底层网络上建立逻辑连接，通常还提供加密和身份认证；Overlay 是建立在 Underlay 之上的逻辑网络，Underlay 提供真实 IP 连通性。

|概念|主要改变|
| -------| -------------------------------------------------|
|VPN|改变主机的路由路径，在虚拟接口/隧道中承载 IP 包|
|Proxy|通常只代理某个应用的流量|

Overlay 没有创造新的物理线路；底层仍受 NAT、防火墙、丢包和带宽影响。是否全流量经过 VPN 取决于路由配置（跨文档引用：ZeroTier 的实现细节见 [ZeroTier专项](/siyuan/其他笔记/计算机网络/学习文档/ZeroTier专项/)）。

### 8.1 Overlay Network 详解（Underlay / Overlay）

> Overlay 是建立在 Underlay 之上的逻辑网络：Underlay 提供真实 IP 连通性，Overlay 在其上封装自己的数据包，不创造新的物理线路。

图示（用真实环境替换原示例地址）：

```
Underlay：宿舍 Internet ───── ISP ───── 实验室 Internet
              ↑                         ↑
              │                         │
Overlay：   AX6 ZT接口 ═══ 加密/封装 ═══ Laptop ZT接口
            192.168.195.4              192.168.195.2
```

- **Underlay（底层网络）** ：真实存在的物理/运营商网络，提供两端之间的 IP 连通性；带宽、延迟、丢包、NAT、防火墙都由它决定。
- **Overlay（叠加网络）** ：在 Underlay 之上用"虚拟网卡 + 隧道封装"搭出的逻辑网络。节点互发数据时，先把 Overlay 内的数据包当作载荷，封装进一层新的包头，再走 Underlay 传输——像"快递套快递"。
- **关键疑问解答**（来自此前学习笔记）：

  - 加入 ZeroTier 后，AX6 虽然知道目标 IP 属于 Overlay 网段，但**不会**在物理局域网里直接 ARP 广播——因为 Overlay 成员分布在世界各地，底层封装必须走真实 Internet 路径（Underlay）；
  - Overlay 没有替代防火墙/NAT：底层仍按真实网络规则走，只是"包被重新打包"了。
- **常见 Overlay 载体**：VPN、ZeroTier、VXLAN、WireGuard。

## 九、网络适配器与多接口

> 网络适配器（网卡）是主机接入网络的硬件或虚拟接口，每个接口可拥有独立的 IP、MAC 和路由。

- 物理适配器：Ethernet、Wi-Fi；虚拟适配器：ZeroTier 虚拟网卡、隧道接口、Loopback。
- 一台主机可同时持有多个 IP：物理 LAN 的 `192.168.6.x`​ 与 ZeroTier 的 `192.168.195.2` 并存；"多 IP"很常见，但隔离与否取决于路由表、监听地址、防火墙和服务配置。

## 十、核心知识速查表

|问题|关键答案|
| -------------------------| -----------------------------------------------------------|
|IP、MAC、端口分别是什么|IP 找跨网络目标，MAC 找当前链路下一跳，端口找主机上的服务|
|`/24` 是多少台主机|`2^8-2=254` 台（网络地址和广播地址不可用）|
|不同网段怎么发数据|交给默认网关，由路由器转发|
|多路由匹配时怎么选|最长前缀匹配，其次 Metric 小的|
|为什么公网无法直连家里|CGNAT / 多层 NAT / 入站防火墙 / 服务监听限制|
|ZeroTier 解决什么|在没有公网入站能力时，建立设备间的逻辑虚拟网络|

## 附录：学习笔记与心得

> 以下为 [从公网、局域网到 ZeroTier：构建属于自己的虚拟局域网（已归档）](/siyuan/已归档/从公网、局域网到-ZeroTier：构建属于自己的虚拟局域网（已归档）/) 学习过程中的个人理解与问答校正。

### A.1 掩码的直观理解

`掩码 & IP = 192.168.6.0/24` 就是该 LAN 的网络 ID；掩码后的数字标识"这台主机在这个 LAN 里的编号"（类比小区号 + 门牌号）。

### A.2 一台设备可以有多个 IP

服务器既可以有公网 IP 供外部访问，也可以有内网 IP 供开发使用——两种方式不冲突，关键在于配置：监听地址、路由表、防火墙分别控制。

### A.3 光猫的角色

光猫本质是"连接互联网（上层已无需考虑）与家庭内网"的接入设备，让内网能访问互联网，也让互联网（在允许时）能访问内网入口。

### A.4 ARP 一句话

ARP 用于把 IP 映射到物理 MAC；目标 MAC 已知则直接发送，未知则发广播询问，得到答复后缓存。

### A.5 Overlay 的疑问澄清

加入 ZeroTier 后，AX6 虽然知道目标 IP 属于 Overlay 网段，但数据包仍交给底层 Internet 路径（Underlay）传输，而不是在物理局域网里 ARP 广播——因为 Overlay 成员分布在世界各地，底层封装必须走真实网络。
