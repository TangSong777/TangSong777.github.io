# ZeroTier 专项 · 知识笔记

> 本笔记融合 [OpenWrt + ZeroTier 个人组网完整方案](/siyuan/其他笔记/计算机网络/OpenWrt-+-ZeroTier-个人组网完整方案/)（部署方案）与 [从公网、局域网到 ZeroTier：构建属于自己的虚拟局域网（已归档）](/siyuan/已归档/从公网、局域网到-ZeroTier：构建属于自己的虚拟局域网（已归档）/)（原理），记录 ZeroTier 组网的知识链条与个人部署实践。

## 一、ZeroTier 核心概念

> ZeroTier 是一种基于虚拟网络接口和 Overlay 的组网软件，使加入同一 Network 的节点可以使用虚拟地址互通，通过控制平面、点对点连接、NAT 打洞或中继完成底层连通。

### 1.1 关键角色

|概念|作用|
| ---------------| ------------------------------------------------------------------------------|
|Network|一个逻辑虚拟网络，有 Network ID 和成员策略|
|Node / Peer|加入网络的设备（ZeroTier 节点）|
|Controller|负责网络成员认证、地址分配与网络配置分发（托管网络经 ZeroTier Central 管理）|
|Managed IP|控制器分配给节点的虚拟 IP（本环境 `192.168.195.x`）|
|Managed Route|向成员下发的目标网络路由（如 `192.168.6.0/24 via 192.168.195.4`）|
|NAT traversal|尝试穿越两端 NAT 建立直连（P2P 打洞）|
|Relay|直连失败时通过中继转发，性能与延迟可能不同|

ZeroTier 不是魔法 VPN：它仍依赖底层 Internet，仍要经过本机路由、虚拟接口、隧道、对端节点和对端路由/防火墙。

### 1.2 与普通 VPN 的区别

- VPN 通常由一台中心服务器终结隧道；ZeroTier 是 P2P 网状结构，节点间尽量直连。
- Overlay 叠加在 Underlay（真实 Internet）之上，底层仍受 NAT、防火墙影响，但不需要公网入站端口。

### 1.3 虚拟网络模型（Overlay 与物理地址的区分）

> 每个成员通过 ZeroTier 虚拟接口获得**虚拟 IP**（本环境 `192.168.195.x`）；虚拟 IP ≠ 物理网卡 IP，也不是宿舍 LAN 地址。

- **物理网络（Underlay）** ：宿舍 Internet 与实验室 Internet 各自真实网络互连，提供底层 IP 连通性。
- **ZeroTier 网络（Overlay）** ：成员在虚拟接口上获得 `192.168.195.0/24`​ 的地址（AX6 `.195.4`​、笔记本 `.195.2`）。
- **关键区别**：`192.168.195.2`​ 不是笔记本 Wi-Fi 网卡的地址，也不是宿舍 LAN 地址，它属于 ZeroTier 虚拟接口；要访问 `192.168.6.100`​（宿舍 LAN），必须**额外存在**"宿舍 LAN 经 AX6 到达"的路由与转发条件（Managed Route 或静态路由 + 转发/防火墙 + 回程）。

## 二、为什么用 ZeroTier 而不是公网直连

> 公网直连在宿舍/家庭环境通常因 CGNAT、多层 NAT 和入站防火墙而不可行；ZeroTier 在有网即可互通。

|对比项|公网直连方案|ZeroTier|
| ------------| --------------------| ------------------------|
|公网 IPv4|必需（且要可入站）|不需要|
|端口转发|必须逐服务配置|不需要开放入站端口|
|光猫桥接|常常必须|不需要|
|CGNAT 环境|基本不可用|可用（P2P 打洞或中继）|
|安全暴露面|向公网开放端口|仅虚拟网络内授权设备|

|网络|网段|成员地址|
| ---------------| -----------------------| ----------------------------|
|家庭 LAN|`192.168.6.0/24`|AX6 网关 `192.168.6.1`​；家庭设备如 `192.168.6.5`|
|ZeroTier 网络|`192.168.195.0/24`​（Network ID `[已隐藏 Network ID]`）|AX6 `192.168.195.4`​；笔记本 `192.168.195.2`​；手机 `192.168.195.3`|

## 四、方案选型：NAT vs 纯路由

> 核心决策：让远程 ZeroTier 客户端访问 `192.168.6.0/24` 时，OpenWrt 采用源 NAT（推荐）还是纯路由（需回程路由）。

### 4.1 NAT 方案（推荐，已采用）

- OpenWrt ZeroTier 插件内置"自动允许客户端 NAT"：远程客户端访问 `192.168.6.0/24`​ 时源地址被转换为 `192.168.6.1`，自动解决回程路由问题。
- 家庭设备无需任何配置；NAS、摄像头、打印机直接可访问。

### 4.2 纯路由方案（需回程路由）

关闭 NAT 时，家庭设备回复的目标是 `192.168.195.x`（真实客户端），必须在家庭 LAN 网关配置回程路由：

```
192.168.195.0/24 via 192.168.6.1
```

否则设备回复无法返回。家庭环境通常不推荐。NAT 方案的代价是：家庭设备看到的所有远程来源都是 `192.168.6.1`，无法区分真实客户端（若要区分，需纯路由 + 回程路由）。

### 4.3 反向访问：让 `192.168.6.5`​ 访问笔记本 `192.168.195.2`（分析）

> 可行，但不是默认可行——需要两处放行（路由器 `lan→zerotier` 转发、笔记本入站防火墙），而回程在已有静态路由下天然成立。

流量路径：

```
192.168.6.5（宿舍内设备）
   ↓ 默认网关 192.168.6.1
AX6：查路由表 → 192.168.195.0/24 走 zt 接口
   （AX6 本身就是 ZeroTier 成员，天然拥有该网段的直连路由）
   ↓ ZeroTier Overlay
笔记本 192.168.195.2（外地）
```

**三个条件逐一分析：**

1. **路由器侧（AX6）** ：需允许 `lan → zerotier`​ 区域的转发。注意：本项目常用配置只开了 `zerotier → lan`​（服务远程客户端访问家庭）；`lan → zerotier`​ 方向需确认或补开，`lan→wan` 的默认允许不一定覆盖 zt zone。
2. **目标侧（笔记本）** ：Windows 防火墙默认拦截"不可信网络"的入站，需对 ZeroTier 接口对应的网络配置放行 ICMP / 对应服务端口，否则包到达笔记本也会被丢弃。
3. **回程**：笔记本回复 `192.168.6.5`​ 时，走已有静态路由 `192.168.6.0/24 via 192.168.195.4`​ → 交给 AX6 → AX6 直连送达。**此方向不需要 NAT**（与"自动允许客户端 NAT"无关——那个只作用于 ZT→LAN 方向的客户端访问）。

**与常用场景对比：**

|方向|是否需要 NAT|主要障碍点|
| -----------------------------| ----------------------------| ------------------------------|
|笔记本 → 6.5（本项目常用）|需要（自动允许客户端 NAT）|AX6 防火墙 `zerotier→lan`|
|6.5 → 笔记本（本场景）|不需要（直连可达）|AX6 `lan→zerotier` 转发 + 笔记本入站放行|

**验证：**

```bash
# 在宿舍内设备（AX6 或 6.5 所在主机）执行
ping 192.168.195.2
```

不通时按顺序排查：AX6 `lan→zt` 防火墙 → 笔记本 Windows 防火墙 → 两端 ZeroTier 在线状态。

## 五、OpenWrt 端配置（AX6）

### 5.0 Controller 侧配置（ZeroTier Central）

> 创建网络与授权成员都在 Controller（ZeroTier Central 网页）完成；它只负责下发策略，不替代 AX6 的转发与防火墙。

1. 创建 ZeroTier Network；
2. 设置 IPv4 Auto-Assign 范围或成员地址策略：`192.168.195.0/24`；
3. 记录 Network ID（`[已隐藏 Network ID]`），不公开授权凭据；
4. 若使用 Managed Route：Destination `192.168.6.0/24`​、Via `192.168.195.4`​（本方案选择**不用**，改由 Windows 静态路由）；
5. 只授权自己的设备（AX6 / 笔记本 / 手机），并检查成员得到的 Managed IP 是否冲突。

### 5.1 ZeroTier 插件

```
ZeroTier 运行：开启
加入 Network ID：[已隐藏 Network ID]
自动允许客户端 NAT：开启
```

### 5.2 防火墙转发

允许 `zerotier → lan` 区域的转发。这是远程流量从虚拟接口进入家庭 LAN 的关键放行。

### 5.3 验证命令（SSH 到 AX6）

```bash
zerotier-cli info
zerotier-cli listnetworks
ip addr
ip route
```

### 5.4 核对清单（OpenWrt 作为 ZeroTier Gateway）

> "能 ping 通 AX6 的 `192.168.195.4`​" 只证明 ZeroTier 节点可达，**不能证明 AX6 已把** **​`192.168.6.0/24`​**​ **转发出去**——转发链路需逐项核对。

需要分别确认：

1. ZeroTier 服务已运行，AX6 已加入并被 Controller 授权；
2. AX6 已获得 ZeroTier 虚拟地址（`192.168.195.4`）；
3. 内核允许从 ZeroTier 接口转发到 LAN（IP forwarding）；
4. OpenWrt 防火墙允许 zerotier → lan 区域的 forwarding。

核对命令（SSH 到 AX6）：

```bash
ip addr                       # 看 ZeroTier 接口与地址
ip route                      # 看默认路由与 LAN 路由
ip rule                       # 策略路由
service zerotier status
logread | grep -i zerotier    # 日志中找 ZT 相关报错
```

⚠️ 版本提醒：OpenWrt 版本可能使用 firewall4/nftables 或旧版 firewall3/iptables，软件包名与配置界面不同；配置以当前版本官方文档为准，**不要直接复制未知版本教程中的 iptables 命令到生产路由器**。

## 六、Windows 客户端配置

### 6.1 降低 ZeroTier 接口优先级（Metric）

```
Ethernet：10~25    WLAN：20~50    ZeroTier：5000
```

设置 ZeroTier IPv4 Metric = 5000，使物理网卡优先。

### 6.2 添加家庭 LAN 静态路由（持久）

不使用 Managed Route 时的替代方案：

```
route -p add 192.168.6.0 mask 255.255.255.0 192.168.195.4 metric 5000
```

### 6.3 双场景路由选择

|场景|路由表现|Windows 选择|
| ------| -------------------------------------| -------------------------------------|
|在家|`192.168.6.0/24 On-link`（低 Metric）+ 静态路由（5000）|本地 LAN（最长匹配相同，比 Metric）|
|外地|无 On-link 路由，仅有 `via 192.168.195.4`|ZeroTier|

验证命令：

```powershell
ping 192.168.6.5
tracert 192.168.6.5
route print -4 | findstr 192.168.6
Get-NetIPInterface -AddressFamily IPv4
```

### 6.4 完全关闭 ZeroTier 的正确方式

> 关闭 ZeroTier 的客户端窗口 ≠ 关闭组网：后台服务 `zerotier-one` 仍在运行，网络连接不会中断。

- 现象：双击关闭 ZeroTier 客户端窗口后，`192.168.195.4`​ 依然能 ping 通——因为 GUI 只是管理界面，真正负责虚拟网卡与隧道的是后台服务（Windows 服务 `ZeroTierOne`），关闭窗口不影响它。
- 需要**完全退出组网**时：

  1. 在 ZeroTier 客户端里 **Disconnect 所有已加入的网络**（先断开各 Network 的连接）；
  2. 再到系统托盘右键 ZeroTier 图标，选择 **Quit**（退出才停止后台服务/卸载虚拟驱动）。
- 验证：

```powershell
Get-Service -Name ZeroTier*    # Running 表示服务仍在运行、连接未断
```

服务停止后，`ping 192.168.195.4` 将不再通。

- `ping 192.168.6.1` ✅（NAT + 防火墙转发生效，可进入家庭 LAN 网关）

## 八、Managed Route 说明

> Managed Route 是在 ZeroTier Central 下发的路由策略：目标属于 `192.168.6.0/24`​ 时，成员把下一跳交给 `192.168.195.4`。

```
Destination: 192.168.6.0/24
Via:         192.168.195.4
```

- 它只解决"客户端把包交给谁"，不自动开启 AX6 的 IP 转发、不放行防火墙、不解决回程路由。
- 本方案选择**不用 Managed Route**，改由 Windows 本地静态路由控制，更简单可控；两种方式二选一，不要同时重复配置。

完整访问过程（从笔记本到家庭设备）：

```
Laptop 192.168.195.2
   ↓ 查询本机路由表
192.168.6.0/24 via 192.168.195.4
   ↓
ZeroTier 虚拟接口 / Overlay
   ↓
AX6 ZeroTier 接口 192.168.195.4
   ↓ OpenWrt 路由与防火墙
LAN 192.168.6.0/24
   ↓
NAS / 家庭设备 192.168.6.100
```

## 九、故障排查速查表

|现象|可能原因|检查方向|
| -------------------------| -----------------------------------------| --------------------------------------|
|外地 ping 不通家庭设备|ZeroTier 未授权 / 防火墙未放行 / 无路由|`zerotier-cli listnetworks`​；zerotier→lan 转发；`route print`|
|在家访问走了 ZeroTier|物理网卡 Metric 不低于 5000|检查本地接口 Metric|
|设备能收到但回包失败|NAT 未开启（回程路由缺失）|确认自动客户端 NAT 开启|
|ZeroTier 不影响正常上网|被添加 `0.0.0.0/0` 默认路由|检查并删除该路由，ZeroTier 只负责 `192.168.6.0/24`|

分层测试顺序：Underlay（两端能上网）→ ZeroTier 状态（在线/授权）→ ZeroTier 地址（ping `192.168.195.4`​）→ AX6 LAN（ping `192.168.6.1`）→ 家庭设备（ping/服务）。ICMP 不通不代表 TCP 服务不通，反之亦然。

### 9.1 分层测试命令（Linux / OpenWrt）

```bash
ping 192.168.195.4          # ① ZeroTier 节点可达
ping 192.168.6.1            # ② AX6 LAN（防火墙允许时）
ping 192.168.6.100          # ③ 家庭设备
ip route get 192.168.6.100  # 确认出接口与下一跳
traceroute 192.168.6.100    # 或 tracepath
nc -vz 192.168.6.100 22     # TCP 端口测试（SSH）
ssh user@192.168.6.100
```

- Windows 对应命令：`ping`​、`tracert`​、`route print -4`​、`Test-NetConnection 192.168.6.100 -Port 22`。
- SMB / HTTP / SSH 能否访问还取决于目标设备的监听地址、防火墙、账户和服务配置；**ICMP 不通不代表 TCP 服务必然不通，反之亦然**。

## 十、MC 多人服务器接入说明

> 让其他玩家通过 ZeroTier 游玩宿舍 MC 服务器（`192.168.6.0/24` 内）。

1. 玩家安装 ZeroTier 客户端，加入网络 `[已隐藏 Network ID]`，管理员在 Central 授权其设备。
2. 为玩家下发 Managed Route `192.168.6.0/24 via 192.168.195.4`，或玩家端手动加静态路由。
3. MC 服务器填局域网 IP（如 `192.168.6.x`​），端口 `25565`。
4. 前提：MC 服务端监听 `0.0.0.0`​，防火墙放行 `zerotier→lan`​ 的 `25565`。
5. 注意：NAT 方案下玩家来源统一显示为 `192.168.6.1`；需区分玩家真实 IP 时改用纯路由 + 回程路由。

# 十一、从一个数据包看懂整个系统

> 用一次真实的远程访问追一个包的旅程（真实环境：笔记本 `192.168.195.2` 在外地 → 宿舍 NAS）。

```
应用：SSH → 192.168.6.100:22
  ↓
TCP：建立到目标 22 端口的连接
  ↓
IP：源 192.168.195.2，目标 192.168.6.100
  ↓
笔记本路由表：192.168.6.0/24 via 192.168.195.4 → 走 ZeroTier 虚拟接口
  ↓
ZeroTier Overlay：把 IP 包封装进隧道（底层走实验室/外地 Internet）
  ↓
AX6：ZeroTier 接口 192.168.195.4 解封装 → 查路由表 → NAT（源改 192.168.6.1）→ 转发到 LAN
  ↓
NAS / 服务器 192.168.6.100 收到请求并回复
```

- ZeroTier 改变的是：笔记本多了虚拟接口/虚拟地址/到家庭 LAN 的逻辑路由；AX6 多了一个可作为网关的 Overlay 接口。
- ZeroTier 没有改变的是：NAS 仍在 `192.168.6.0/24`、底层仍是真实 Internet、NAT 与防火墙规则照样生效——这就是"Overlay 叠加在 Underlay 之上"的完整含义。

# 十二、安全注意事项

- ZeroTier Network ID 不是完整秘密，但**成员授权和访问策略必须严格控制**——任何加入者都在你的虚拟网络内。
- 不要把整个家庭 LAN 无条件暴露给所有成员；按端口/设备限制访问（如 MC 只放 `25565`、NAS 只给自己设备）。
- 定期检查 ZeroTier Central 的授权设备列表，移除陌生/不再使用的设备。
- 配合 Tunnel 方案时，板卡不向公网开放任何入站端口，SSH 也因此更安全（22 端口不对公网暴露）。

- 日志、抓包和配置中可能包含用户名、地址、令牌等**敏感信息，不要公开分享**；
- 记录哪些成员能访问哪些网段，**定期删除不用的节点**；
- NAT 不是安全边界的替代品，Overlay 网络也不是自动可信网络——不要因为"走 ZeroTier"就关闭目标设备防火墙。

# 十三、核心知识速查表

|问题|关键答案|
| ------------------------------| -----------------------------------------------------------|
|ZeroTier 有什么用|在没有公网入站能力时，建立设备间的逻辑虚拟网络（Overlay）|
|加入同一 Network 需要什么|网络 ID + Controller 授权，获得虚拟网段内地址|
|为什么这里不用 Managed Route|客户端路由由 Windows 本地静态路由控制，更简单可控、可迁移|
|NAT 方案下家庭设备看到的来源|统一为 `192.168.6.1`（无法区分真实客户端）|
|回程路由解决什么|纯路由模式下家庭设备回复 `192.168.195.x` 的路径可达问题|
|能 ping 通 `192.168.195.4` 等于什么|只等于 ZeroTier 节点可达；验收要 ping 家庭内网真实设备|

## 附录：学习笔记与心得

> 以下为组网学习与部署过程中的个人理解与记录。

### A.1 远程访问的心智链条

遇到网络问题按这条链自查：应用（访问哪个服务端口）→ 传输层（TCP/UDP，端口是否监听）→ IP 层（源/目标属于哪个网络）→ 路由（本机路由表把包交给谁）→ 二层（ARP 找下一跳 MAC）→ 底层与对端（防火墙/NAT/服务配置）。

### A.2 在家/在外自动切换的本质

本质是 Windows 路由表里同一条 `192.168.6.0/24` 存在两个"候选出口"：在家时 On-link 直连（低 Metric）胜出，外地时只剩 ZeroTier 静态路由可用——不需要任何手动切换逻辑。

### A.3 部署心得

- 能 ping 通 `192.168.195.4`​ 只证明 ZeroTier 节点可达；能 ping 通 `192.168.6.1`​ 才证明转发链路打通；**真正的验收指标是家庭内网真实设备**。
- 重复路由（同目标同网关不同 Metric）不影响使用，但建议清理为一条以保持路由表干净。
